# Resume Processing — Requirements

## 背景与目标

SubForge 面向长音频和批量音轨处理，ASR 与 LLM 翻译都可能耗时较久，也可能因用户中断、网络错误、限流或进程异常而失败。断点续跑能力的目标是让用户重新执行同一输入时尽量复用已完成结果，从最近的可靠进度继续处理，减少重复 ASR 和重复 LLM 调用，同时保留强制从头处理的能力。

## 范围

- In scope:
  - 在统一位置保存每个处理任务的断点状态文件
  - 默认复用已存在的源语言 SRT，跳过对应 ASR 阶段
  - 提供强制从头开始的用户开关，忽略已有产物和断点状态
  - 翻译阶段支持批次级断点恢复
  - 中断或失败后重新运行同一任务时从已完成批次后继续
  - 对断点状态损坏、不匹配或过期的情况给出明确处理行为
- Out of scope:
  - GUI 断点管理界面
  - 跨机器同步断点状态
  - 对已生成字幕内容进行质量校验或人工编辑合并
  - 多目标语言一次性翻译
  - 改变现有 ASR、时间轴微调和 LLM 翻译质量策略

## 需求(EARS)

### R1. 断点状态存储

- **R1.1** WHEN 系统开始处理一个媒体文件 THE SYSTEM SHALL 在用户配置目录下的统一任务状态区域保存该文件的断点状态。
- **R1.2** WHEN 同一媒体文件再次被提交处理 THE SYSTEM SHALL 查找并加载与该媒体文件对应的断点状态。
- **R1.3** IF 断点状态与当前媒体文件、源语言、目标语言或关键处理配置不匹配 THEN THE SYSTEM SHALL 不使用该断点状态并记录可理解的提示。
- **R1.4** IF 断点状态文件缺失 THEN THE SYSTEM SHALL 按无断点的新任务处理。
- **R1.5** IF 断点状态文件损坏或无法解析 THEN THE SYSTEM SHALL 忽略该断点状态、记录警告，并继续处理当前文件。

### R2. ASR 阶段恢复

- **R2.1** WHEN 用户处理的媒体文件旁已存在同名源语言 SRT THE SYSTEM SHALL 默认复用该源语言 SRT 并跳过 ASR 阶段。
- **R2.2** WHEN 用户处理的媒体文件已有断点状态且该状态标记 ASR 已完成 THE SYSTEM SHALL 复用已完成的源语言字幕并跳过 ASR 阶段。
- **R2.3** IF 已存在的源语言 SRT 无法读取、为空或格式无效 THEN THE SYSTEM SHALL 不复用该 SRT，并重新执行 ASR 阶段。
- **R2.4** WHEN ASR 阶段成功生成源语言字幕 THE SYSTEM SHALL 将 ASR 完成状态记录到断点状态中。

### R3. 完整结果恢复

- **R3.1** WHEN 用户处理的媒体文件旁已存在完整目标语言 SRT THE SYSTEM SHALL 默认跳过该文件的全部处理阶段。
- **R3.2** IF 已存在的目标语言 SRT 无法读取、为空或格式无效 THEN THE SYSTEM SHALL 不复用该 SRT，并继续按断点状态或源语言 SRT 恢复处理。
- **R3.3** WHEN 系统跳过已有完整目标语言 SRT 对应的文件 THE SYSTEM SHALL 向用户提示该文件已完成并被跳过。

### R4. 强制从头开始

- **R4.1** WHERE 用户显式启用强制从头开始选项 THE SYSTEM SHALL 忽略已有源语言 SRT、已有目标语言 SRT 和已有断点状态。
- **R4.2** WHERE 用户显式启用强制从头开始选项 THE SYSTEM SHALL 从 ASR 阶段重新处理媒体文件。
- **R4.3** WHEN 强制从头处理成功推进 THE SYSTEM SHALL 用新的处理进度覆盖该媒体文件的旧断点状态。

### R5. 翻译批次级恢复

- **R5.1** WHEN 翻译阶段开始 THE SYSTEM SHALL 将待翻译字幕按批次追踪处理状态。
- **R5.2** WHEN 一个翻译批次成功返回并通过基本解析 THE SYSTEM SHALL 将该批次的翻译结果保存到断点状态中。
- **R5.3** WHEN 同一任务恢复翻译 THE SYSTEM SHALL 跳过断点状态中已完成且配置匹配的翻译批次。
- **R5.4** WHEN 同一任务恢复翻译 THE SYSTEM SHALL 只提交未完成或无效的翻译批次给 LLM。
- **R5.5** WHILE 翻译批次并发执行 THE SYSTEM SHALL 保证恢复后的最终目标语言 SRT 按原始字幕顺序输出。
- **R5.6** IF 某个翻译批次失败 THEN THE SYSTEM SHALL 保留其它已成功批次的断点结果，并将该任务标记为可恢复失败。
- **R5.7** WHEN 所有翻译批次完成 THE SYSTEM SHALL 写出完整目标语言 SRT，并将翻译完成状态记录到断点状态中。

### R6. 用户反馈与日志

- **R6.1** WHEN 系统跳过 ASR 阶段 THE SYSTEM SHALL 向用户提示已复用已有源语言字幕。
- **R6.2** WHEN 系统跳过已完成翻译批次 THE SYSTEM SHALL 在日志中记录跳过的批次数量。
- **R6.3** WHEN 系统因为强制从头开始而忽略断点 THE SYSTEM SHALL 在日志中记录该行为。
- **R6.4** WHEN 断点状态不可用、损坏或不匹配 THE SYSTEM SHALL 记录原因但不中断整个批量处理。

### R7. 批量处理兼容性

- **R7.1** WHEN 用户提交多个文件 THE SYSTEM SHALL 为每个文件独立维护断点状态。
- **R7.2** WHEN 批量处理中某个文件恢复失败 THE SYSTEM SHALL 不影响其它文件继续处理。
- **R7.3** WHEN 多个文件并发处理 THE SYSTEM SHALL 避免不同文件的断点状态互相覆盖。

## 验收场景(Given-When-Then)

### S1. 已有源 SRT 时默认跳过 ASR ← R2.1, R5.1

- **Given** 一个媒体文件 `audio.m4a` 和同目录下已存在的 `audio.srt`
- **When** 用户再次执行处理命令且未启用强制从头开始
- **Then** 系统复用 `audio.srt`，不执行 ASR，并继续进入翻译阶段

### S2. 完整目标 SRT 默认跳过整个文件 ← R3.1, R3.3

- **Given** 一个媒体文件 `audio.m4a` 和同目录下已存在完整的 `audio_zh.srt`
- **When** 用户再次执行处理命令且未启用强制从头开始
- **Then** 系统跳过该文件的 ASR 与翻译阶段，并提示该文件已完成

### S3. 强制从头开始忽略旧结果 ← R4.1, R4.2, R6.3

- **Given** 一个媒体文件已有 `audio.srt`、`audio_zh.srt` 和断点状态
- **When** 用户执行处理命令并启用强制从头开始选项
- **Then** 系统忽略已有产物和断点状态，从 ASR 阶段重新处理

### S4. 翻译失败后批次级恢复 ← R5.2, R5.3, R5.4, R5.6

- **Given** 一个媒体文件共有 5 个翻译批次，其中前 3 个批次已成功保存到断点状态，第 4 个批次失败
- **When** 用户再次执行同一处理命令
- **Then** 系统跳过前 3 个已完成批次，只向 LLM 提交第 4 和第 5 个批次

### S5. 恢复后目标 SRT 顺序正确 ← R5.5, R5.7

- **Given** 翻译结果一部分来自断点状态，一部分来自本次 LLM 调用
- **When** 所有批次最终完成
- **Then** 系统写出的目标语言 SRT 条目顺序与源语言 SRT 条目顺序一致

### S6. 损坏断点不阻断处理 ← R1.5, R6.4, R7.2

- **Given** 某个媒体文件对应的断点状态文件内容损坏
- **When** 用户提交该媒体文件和其它文件一起批量处理
- **Then** 系统记录警告，按无断点任务处理该文件，并继续处理其它文件

### S7. 不匹配断点被忽略 ← R1.3, R6.4

- **Given** 某媒体文件存在断点状态，但目标语言或关键处理配置与当前命令不一致
- **When** 用户执行当前命令
- **Then** 系统忽略旧断点并记录原因，避免混用不兼容结果

## 非功能需求

- **可靠性**：进程被中断或 LLM 调用失败时，已完成批次的断点结果不应丢失。
- **性能**：恢复任务时不得重复调用已完成批次的 LLM 翻译。
- **兼容性**：断点续跑应兼容 Windows 优先的使用场景，并保持现有 CLI 批量处理行为。
- **可观测性**：所有恢复、跳过、忽略断点和强制重跑行为应通过日志可追踪。
- **安全性**：断点状态不得保存 LLM API Key 或其它敏感凭据。
