# 字幕存储与校验

用户视角的说明见[字幕校对](../subtitle-revision.md)与[片段重跑](../segment-reprocess.md)。

## 原则

- 字幕时间轴的**事实来源**是正式 SRT 文件，不信任模型输出的时间戳；
- 模型只提供文本，时间由 SubForge 生成、校验、钳制；
- SQLite 不存字幕正文，字幕文件与快照才是事实来源，随 Library 迁移。

## 编辑校验规则

- 时间不得为负数；
- 开始时间必须早于结束时间；
- 结束时间不得超过媒体时长；
- 不得与前一条重叠。

Whisper 对结尾静音会幻觉出「ご視聴ありがとうございました」一类尾句，时间戳可能超出媒体长度。这类**历史**脏数据会在编辑 / 片段替换前就地钳制到媒体时长，而不是让整份提交被拒；**显式提交**的越界新值仍会被拒绝。

## 结构操作（API）

`POST /api/tracks/{track_id}/subtitles/structure`，`action` 取值：

| 操作 | 说明 |
|------|------|
| `merge` | 用第一条开始、最后一条结束，可先确认合并后的源文 / 译文 |
| `split` | 指定拆分时间 + 前后半原文 / 译文 |
| `delete` | 源字幕与翻译字幕一起删 |

当前 React 前端只暴露了文本编辑、±0.5 秒平移和删除；合并、拆分、恢复自动版本由后端支持，尚未在新 UI 中提供入口。

## 快照

- 每次正式写入前自动保存「上次修改前」快照；
- 撤销 / 恢复都是**原子**操作：源字幕与翻译字幕要么都成功、要么都不变；
- 恢复接口：`POST /api/tracks/{track_id}/subtitles/restore/{snapshot}`。

## 可编辑的时间范围

- 起止时间可超出字幕边界，覆盖无字幕区间；替换范围以这里的时间为准
- **留空 = 覆盖到音频边界**：结束留空/超过媒体长度 → 覆盖到音频末尾；开始留空 → 覆盖到音频开头
- 越界提交前会弹确认框告知「将覆盖到音频末尾/开头，是否继续」
- 两者皆留空 → 回退为所选字幕条目的区间（兼容旧行为）
- 后端对越界结束时间钳制到媒体时长做确定性兜底

## 处理器

=== "Whisper 短片段"

    - 模型：`large-v3` / `medium`
    - 场景：ASMR / 普通语音（应用 ASMR 预设）
    - 需要翻译配置（转写后交文本 LLM 翻译）
    - 片段带前后 2 秒上下文识别，但候选只替换所选范围

=== "音频模型（Gemini 等）"

    - 选择带 `transcribe` 能力的[模型 Profile](model-profiles.md)
    - 处理模式：转写后翻译，或一次生成双语
    - 支持识别提示词（人名、作品名、专有词）
    - 超过 Profile 单次上限自动按语音区间分块

## 候选语义

- 候选**不是**正式字幕：不参与播放和导出，只有确认后才写入
- 确认时才做范围替换：范围外的既有字幕保留，范围首尾的空隙自动补空段
- 每次确认前自动保存快照，可撤销
- 放弃只改变任务状态，正式字幕不动
- 候选结果持久化在 SQLite，重启后仍可打开评审

## 候选已按语句切分

模型返回结构化结果时按自然语句切成多条；时间戳只在「单调、在范围内」时采用，否则按文本长度比例重新分配——**时间轴始终由 SubForge 确定性生成**。
